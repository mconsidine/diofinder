## Role

`tetra3rs` provides two things consumed by the pipeline:

1. **Rust-backed Python wheel** (`tetra3rs-*.whl`) — the plate solver used on both the Pi and in CI benchmarking.
2. **`SolverDatabase.generate_from_gaia()`** — called by `scripts/generate_databases.py` (on an x86_64 CI runner, using the x86 wheel) to generate `tetra3rs_13deg.bin`.

---

## Build Configuration Decisions

### Build Tool: cibuildwheel (not maturin)

tetra3rs uses `setuptools-rust` as its build backend, which requires the Python interpreter at build time to match the target architecture. This prevents the maturin cross-compilation approach used for sycamore-extract and olive-solve.

**Decision: cibuildwheel + QEMU for arm targets.**  
For aarch64 and armv7, a QEMU-emulated environment is required. This is slow (~1 hour per Python version under QEMU for aarch64) but currently the only correct approach for setuptools-rust cross-builds.

### Python Version Strategy

**Regular pipeline (aarch64):** cp313 only.  
Rationale: Cutting from cp311+cp312+cp313 to cp313-only reduced the aarch64 QEMU build time from ~3 hours to ~1 hour. The Pi OS Bookworm deployment target is Python 3.13; there is no current user need for cp311/cp312 aarch64 wheels.

**x86_64 (Stage 2 / CI benchmark):** cp313 only. Native cibuildwheel, no QEMU, ~30 minutes.

**manual-build.yml:** cp311, cp312, cp313, or `many` (all three). Use `many` to build the full wheel set if needed.

### RUSTFLAGS by Architecture

| arch | RUSTFLAGS |
|---|---|
| aarch64 | `-C target-cpu=cortex-a53 -C codegen-units=1` |
| armv7 | `-C target-cpu=cortex-a7 -C codegen-units=1` |
| x86_64 | (none) |
| x86 (i686) | (none) |

`CARGO_PROFILE_RELEASE_PANIC=abort` is set for all architectures.

### cibuildwheel Environment

```yaml
CIBW_BEFORE_ALL_LINUX: curl … | sh -s -- -y --profile minimal  # install rustup
CIBW_ENVIRONMENT: PATH="$HOME/.cargo/bin:$PATH" RUSTFLAGS="…" CARGO_PROFILE_RELEASE_PANIC="abort"
CIBW_BEFORE_BUILD: pip install setuptools>=68 setuptools-rust>=1.10
```

## Database Generation Role

The x86_64 wheel is installed in the `build-databases` CI job to run `SolverDatabase.generate_from_gaia()`. The Gaia DR3 catalog is fetched via the `gaia-catalog` PyPI package (no manual catalog download needed).

**Database parameters:**

| Parameter | Value |
|---|---|
| `max_fov_deg` | 14.0 |
| `min_fov_deg` | 10.5 |
| `star_max_magnitude` | 8.0 |
| `epoch_proper_motion_year` | 2026.0 |
| `catalog_path` | None (uses gaia-catalog PyPI package) |

**Output file:** `tetra3rs_13deg.bin` (the "13deg" suffix is a legacy label; actual FOV is 10.5–14°)

## Recommendations

- The setuptools-rust dependency is the primary constraint forcing cibuildwheel + QEMU for arm builds. If tetra3rs is ever migrated to a pure maturin build backend, cross-compilation would become possible and arm build times would drop from ~1 hour to ~5 minutes.
- Pin `TETRA3RS_REF` to a release tag for production.
- If cp311/cp312 aarch64 wheels are needed (e.g., a Pi OS version with older Python), use `manual-build.yml` with `component=tetra3rs, architecture=aarch64, python-version=many`. Budget ~3 hours for QEMU.
